# LogAzac

> **로그 파일을 업로드하면 데이터를 파싱하고, 규칙에 따라 이상 로그를 탐지하여 결과를 저장·조회할 수 있는 로그 분석 웹 서비스**

## 📌 프로젝트 소개

**LogAzac**은 장비에서 발생하는 로그 파일을 사람이 직접 확인하던 작업을 자동화하기 위해 시작한 개인 프로젝트입니다.

과거 자판기 약 350대를 운영하며 장애 발생 시 로그를 직접 확인하고, 문제 원인을 분석한 뒤 개발사에 로그와 분석 내용을 전달했던 경험을 바탕으로 기획했습니다.

단순히 로그를 화면에 출력하는 것이 아니라,

**로그 업로드 → 파싱 → 이상 여부 판단 → DB 저장 → 검사 이력 조회**

과정을 하나의 웹 서비스로 구현하는 것을 목표로 합니다.

---

## 🎯 개발 목적

기존 로그 분석 업무에서는 장애가 발생하면 로그 파일을 직접 열어 필요한 데이터를 찾고 정상 로그와 비교해야 했습니다.

이 과정에서 다음과 같은 문제가 있었습니다.

* 많은 로그를 사람이 직접 확인해야 함
* 비슷한 장애를 반복해서 분석해야 함
* 이상 유형을 일관된 기준으로 관리하기 어려움
* 과거 검사 결과를 다시 확인하기 어려움

LogAzac에서는 이러한 과정을 규칙 기반으로 자동화하여 **운영·QA·기술지원 업무에서 활용할 수 있는 로그 분석 시스템**을 구현하고자 했습니다.

## 🔍 분석 대상 로그 예시

```text
DEVICE_ID=VM001
STATE_CODE=NORMAL
TOY01=10,1000,상품A
TOY02=5,2000,상품B
RESULT=OK
DEVICE_TYPE=VENDING
```

정상 로그의 필드 구조를 기준으로 데이터를 파싱한 뒤 이상 여부를 판단합니다.

### 주요 이상 로그 유형

* 구분자 구조 오류
* 필수 필드 누락
* 슬롯 데이터 누락
* 상품명 누락
* 가격 데이터 이상
* RESULT 값 누락
* 슬롯 코드 형식 오류
* 잘못된 데이터 구조

예시:

```text
CASHS=0||||||||
```

정해진 로그 구조와 다른 구분자가 반복되는 경우 **구조 이상 로그**로 탐지합니다.

## ✨ 주요 기능

### 1. 회원 관리

* 회원가입
* 로그인 / 로그아웃
* 로그인 사용자별 검사 이력 관리

### 2. 로그 파일 업로드

* 로그 파일 업로드
* 파일명 저장
* 파일 크기 저장
* 로그 라인 수 저장
* 로그 종류 관리
* 업로드 일시 저장

### 3. 로그 분석

업로드된 로그를 읽어 각 데이터를 분석합니다.

```text
로그 파일
   ↓
파일 읽기
   ↓
로그 파싱
   ↓
세션 데이터 분리
   ↓
슬롯 데이터 분리
   ↓
이상 판단 규칙 적용
   ↓
분석 결과 DB 저장
```

### 4. 이상 로그 탐지

분석 과정에서 정상 규칙과 맞지 않는 데이터를 탐지하여 별도로 저장합니다.

이상 로그에는 다음 정보를 기록합니다.

* 이상 판단 규칙
* 탐지된 값
* 이상 내용
* 발생 세션
* 탐지 일시

### 5. 검사 이력

로그인한 사용자가 자신이 분석한 로그 파일을 확인할 수 있습니다.

* 검사 파일명
* 검사 일자
* 로그 종류
* 검사 결과
* 이상 로그 수

### 6. 검사 결과 상세 조회

검사 이력에서 특정 검사 결과를 선택하면 분석된 데이터를 상세하게 확인할 수 있습니다.

* 파일 정보
* 검사 정보
* 세션 정보
* 탐지된 이상 로그
* 이상 판단 내용

### 7. 검사 이력 삭제

사용자가 필요하지 않은 검사 기록을 삭제할 수 있습니다.

검사 데이터와 연결된 분석 결과도 함께 관리할 수 있도록 구성했습니다.

## 🗄 Database

로그 데이터를 파일 단위로만 저장하지 않고 분석 목적에 따라 분리하여 관리합니다.

### 주요 테이블

| Table         | Description   |
| ------------- | ------------- |
| `LOG_FILE`    | 업로드된 로그 파일 정보 |
| `LOG_SESSION` | 로그 내부의 세션 데이터 |
| `LOG_SLOT`    | 세션별 슬롯 데이터    |
| `ANOMALY`     | 탐지된 이상 로그     |
| `RULE`        | 이상 판단 규칙      |
| 사용자 관련 테이블    | 회원 및 로그인 정보   |

### 데이터 관계

```text
USER
 │
 └── LOG_FILE
       │
       └── LOG_SESSION
             │
             ├── LOG_SLOT
             │
             └── ANOMALY
                    │
                    └── RULE
```

로그 파일 하나에 여러 세션이 존재하고, 하나의 세션에는 여러 슬롯과 이상 탐지 결과가 존재하도록 구성했습니다.

## 🧩 구현 과정에서 해결한 문제

### 사용자별 검사 이력 분리

초기 개발 과정에서 검사 이력 조회 시 특정 사용자 번호가 고정되어 다른 사용자의 검사 결과가 조회되는 문제가 있었습니다.

로그인 세션의 사용자 번호를 기준으로 조회하도록 변경하여 사용자별 검사 기록이 분리되도록 수정했습니다.

### MyBatis Parameter Binding

검사 결과를 조회하는 과정에서 Mapper XML에서 사용하는 파라미터명과 Java Mapper에서 전달하는 파라미터가 일치하지 않아 다음과 같은 오류가 발생했습니다.

```text
Parameter 'fileNo' not found
```

Mapper 메서드의 파라미터와 MyBatis XML의 파라미터명을 맞춰 해결했습니다.

### 회원가입 후 페이지 이동 오류

회원가입 이후 존재하지 않는 `/user/login` 리소스로 이동하면서 404 오류가 발생했습니다.

Controller Mapping과 View 경로를 다시 정리하여 회원가입 이후 로그인 화면으로 정상 이동하도록 수정했습니다.

### 검사 결과 삭제

검사 이력에서 선택한 분석 결과를 삭제할 수 있도록 구현하고, 연결된 데이터 관계를 확인하면서 삭제 로직을 구성했습니다.

## 💡 프로젝트에서 중점적으로 다룬 부분

이 프로젝트는 단순 CRUD 구현보다는 **실제 운영 과정에서 발생했던 로그 분석 업무를 시스템으로 전환하는 것**에 중점을 두었습니다.

특히 다음 과정을 직접 설계하고 구현하고 있습니다.

```text
비정형 로그
    ↓
구조 분석
    ↓
데이터 파싱
    ↓
정상 / 이상 판단
    ↓
데이터 구조화
    ↓
DB 저장
    ↓
사용자에게 분석 결과 제공
```

이를 통해 Java/Spring 웹 개발뿐만 아니라 **로그 분석, SQL, 데이터 구조 설계, 장애 원인 분석 및 트러블슈팅 과정**을 함께 경험하는 것을 목표로 하고 있습니다.
